# LearnLens — 교수용 차시 퀴즈 분석 데모

> 이 데모는 Moodle 5.3 Boost 테마의 화면 구성을 참고한 **비공식** 데모이며 Moodle HQ와 관련이 없습니다. 모든 데이터는 **가상**입니다.

교수가 한 차시 퀴즈에서 **어떤 개념에서, 어떤 문항 근거로, 어떤 학생이 틀렸는가**를 확인하고, 보충 그룹을 저장하거나 근거가 부족하면 그룹화를 보류할 수 있게 하는 MVP입니다.

- 스택: Next.js 16 (App Router, 정적 export) · TypeScript · vanilla CSS · 차트 라이브러리 없음(SVG/표 직접 구현)
- 배포: GitHub Pages (`.github/workflows/deploy.yml`)
- 데이터 원천: 퀴즈 응답은 **xAPI Statement**(`public/xapi/quiz-w5.statements.json`)이고, 분석 입력은 이 파일에서 변환해 만든다
- 상태 저장: 브라우저 localStorage (이 브라우저에만 저장, 기기 간 공유 없음)

| 경로 | 내용 |
|---|---|
| `/` | 소개 페이지 (기능 설명·활용 순서, "시작해보기" → `/courses/`). 상단바·과정 인덱스 없음 |
| `/courses/` | My courses 과정 홈 (Moodle 스타일 섹션·활동 목록, 과정 인덱스 드로어) |
| `/quiz/quiz-w5/` | 퀴즈 활동 화면 |
| `/quiz/quiz-w5/analysis/` | 분석 대시보드: 응시 현황 배너 · **AI 요약 초안**(사실 칩·편집·확정·복사) · 개념 취약도 Heatmap · 문항분석 · 동시 오답 패턴 · 문항 유사도 네트워크 |
| `/quiz/quiz-w5/student/<id>/` | 학생 상세: 개념별 오답률, 복습 제안, 문항별 응답 |
| `/quiz/quiz-w5/qmatrix/` | **AI 태그 초안**(AI 추가·제거 비교, 문항별 반영) · 개념 태그(Q-matrix) 편집과 미리보기(문항별 출처) · **개념 관계**(AI 초안 → 확정, 중복 현황) |
| `/quiz/quiz-w5/groups/` | 보충 그룹 제안(개념별 규칙 / **개념 묶음(확정 관계, 합집합)** / 참고용 "오답이 비슷한 학생끼리 묶기"(계층 군집) / "비슷한 학생이 몰린 무리 찾기"(DBSCAN)), 저장·보류·거부. 탐색 보기는 그림 없이 묶음 카드만 보여 줌 |
| `/essay/quiz-w5e/` | 서술형 퀴즈(2문항, 루브릭 기준 3개 × 0·1·2) 소개와 루브릭 |
| `/essay/quiz-w5e/grading/` | **AI 우선 배치**(2026-11-11): 위에 AI 채점 진행 막대(상태별 건수·일괄 제안), 아래 대기열(상태 필터) | 답안(근거 하이라이트) | AI 제안·결정. 수락 / 수정 후 확정 / 직접 채점, 확정 뒤 "다음 답안 →" |
| `/essay/quiz-w5e/analysis/` | 확정률, **AI 요약 초안**(확정 점수로 만든 사실만), 개념 점수율, 기준별 분포, AI 제안 vs 교수 확정, AI 제안 vs 기준 채점(생성/보류 분리) |
| `/settings/ai/` | 제공자(**AI**·Mock·Gemini·Anthropic·OpenAI 호환), 모델, 현재 브라우저의 개인 키 또는 로컬 중계 연결 확인, **작업별 모델** |

## 개발

```bash
npm install
npm run dev          # http://localhost:3000
npm test             # 분석 로직 단위 테스트 (Vitest)
npm run typecheck
npm run lint
npm run gen:data     # 가상 데이터 재생성 (시드 고정, src/data/course.json·quiz-w5.json(정의)·roster.json, public/xapi/ Statement와 검증 보고서)
npm run gen:essays   # 서술형 가상 답안 재생성 (src/data/quiz-w5e.json, docs/essay-review.md)
npm run build:pages  # /intube-quiz-analytics/ 하위 경로로 정적 빌드 → out/
npm run ai:smoke -- essay|tag|relation|summary gemini|lg [모델]  # 실연 1건 (.env의 GEMINI_API_KEY·LG_API_KEY, 재시도 없음)
npm run ai:proxy     # 기본 AI 중계 http://127.0.0.1:8787 (로컬은 npm run dev와 함께, 시연은 Codespaces: docs/demo-relay.md)
```

**기본 AI로 쓰려면** 터미널 두 개에서 `npm run ai:proxy`와 `npm run dev`를 띄우고 `http://localhost:3000`으로 접속합니다. 로컬 실행에서는 기본 AI가 기본 제공자이고, 공개 배포 사이트에서는 Mock이 기본입니다. 제공자 서버는 브라우저 CORS를 허용하지 않아(사전 요청에 401, 2026-11-11 측정) 브라우저가 직접 부를 수 없습니다. 중계가 `.env`(공개 중계는 Secret)의 `LG_API_KEY`를 붙여 대신 부르므로 키는 브라우저로 오지 않습니다. 중계는 기본이 `127.0.0.1`에만 열리고, 허용한 Origin(`http://localhost:3000`, `http://127.0.0.1:3000`, `.env`의 `AI_RELAY_ORIGINS`로 변경)에서 온 JSON 요청만 전달하며, 업스트림 호출은 한 번에 1건·1.1초 간격입니다(초당 1건 한도).

**배포 사이트에서 기본 AI를 쓰려면(시연용, 2026-11-11 U16)** GitHub Codespaces에서 중계를 시연 때만 띄우고(`RELAY_HOST=0.0.0.0`, 접속 코드 `AI_RELAY_CODE`, 하루 예산 `AI_RELAY_BUDGET=20`, 허용 Origin `AI_RELAY_ORIGINS`가 모두 있어야 시작합니다), 사이트의 `/settings/ai/`에서 중계 주소(https)와 접속 코드를 입력합니다. 화면에 "호출 n회 · 소요 s초"와 "오늘 호출 n/20"이 보입니다. 절차와 한계는 [`docs/demo-relay.md`](docs/demo-relay.md).

`.env`는 커밋하지 않습니다(`.gitignore`). 키를 `NEXT_PUBLIC_` 변수로 바꾸면 정적 번들에 들어가 공개되므로 쓰지 않습니다. 기본 AI 외의 제공자는 브라우저 화면의 `/settings/ai/`에 키를 직접 입력합니다.

## 지표와 한계

지표 정의, 분모, 표시 문구는 [`docs/decisions.md`](docs/decisions.md)에 있습니다. 요약:

- **개념 관찰 오답률** = 틀린 개념 태그 문항 수 / 개념 태그 문항 수. 개념 숙달 확률이 아닙니다. 태그 문항이 없으면 0%가 아니라 "자료 없음"입니다.
- 한 문항에 여러 개념을 태그하면 오답이 모든 태그 개념에 똑같이 반영됩니다.
- **동시 오답 Jaccard**는 공동 오답자 수와 함께 표시하고, 공동 오답자가 2명 미만이면 "근거 부족"으로 처리합니다. 함께 틀렸다는 것이 같은 개념을 측정한다는 뜻은 아닙니다.
- **변별도**는 Moodle 방식(문항 점수와 나머지 총점의 상관)이며 25명 기준 참고값입니다.
- **학생 군집**(화면 이름 "오답이 비슷한 학생끼리 묶기")은 오답 집합 Jaccard 거리 + 평균 연결 계층 군집입니다. 덴드로그램은 그리지 않습니다. 묶음 수 k는 교수가 고르고, "문항 하나를 빼고 다시 묶으면 몇 명이 다른 묶음으로 옮겨 가는가"(민감도)를 함께 보여줍니다. 묶음 번호는 임의라서 두 분할의 묶음을 일대일로 가장 잘 맞춘 뒤 셉니다(데모 데이터 k=3에서 최대 8명).
- **문항 유사도 네트워크**는 연결 기준을 "동시 오답"과 "개념 태그 공유" 중 하나만 고릅니다(혼합 금지). 동시 오답 기준에서는 공동 오답자 2명 미만인 쌍을 그리지 않습니다. 노드 배치는 개념 순 원형(결정적)입니다.
- **밀도 기반 탐색(DBSCAN)**(화면 이름 "비슷한 학생이 몰린 무리 찾기")은 원래 Jaccard 거리에서 계산하고(최소 인원 minPts는 자기 포함), 노이즈는 "현재 조건에서 그룹 미배정"으로 표시합니다. 반경 eps는 "틀린 문항이 (1 − eps) 이상 겹침"으로 보여 줍니다. 2D 산점도와 k-거리 그래프는 교수가 읽기 어렵고 결정에 쓰이지 않아 뺐습니다(decisions U14). 데모 데이터에서는 eps 0.40→0.45만으로 그룹 수가 4→2로 바뀌고, 문항 하나를 빼면 최대 11명이 다른 무리로 옮기거나 미배정 여부가 바뀔 만큼 불안정합니다.
- **Q-matrix 점검(탐색)**은 개념 태그 화면의 접힌 카드에 있습니다. 문항 쌍 phi를 "공유 태그 있음/없음"으로 묶은 평균과 그 차이만 요약하고, 학생 1명을 뺐을 때의 범위를 함께 보여줍니다. 쌍 판정, 유의성, 문항별 점수, 인과·선수 관계 해석은 하지 않습니다. 25명 규모에서는 쌍 하나의 값이 크게 흔들리기 때문입니다. 근거는 [`docs/decisions.md`](docs/decisions.md) §7에 있습니다.
- 실루엣·부트스트랩 안정성은 소표본에서 신뢰도로 오해되기 쉬워 넣지 않았습니다.
- 가상 데이터에는 학생 프로필(최단 경로 취약, 정렬 개념 취약, 시간복잡도 오해 등)을 심어 두었습니다. 화면에서 이 패턴이 보이는 것은 생성 가정의 재현이지 분석의 교육적 타당성 검증이 아닙니다.

## 서술형 AI 채점 제안

결정과 지표 정의는 [`docs/decisions.md`](docs/decisions.md) §6, Moodle 5.3 연동 설계는 [`docs/moodle-ai-integration.md`](docs/moodle-ai-integration.md)에 있습니다.

- **예시 데이터를 만드는 방법:** quiz-w5와 같은 학생·프로필에서 루브릭 기준마다 "의도 수준"을 뽑고, 기준×수준 문장 뱅크로 답안을 조합합니다. 의도 수준이 기준 채점이 됩니다. 경계 사례(무응답, 짧은 답, 주제 이탈, 지시문 주입, 글자 수 초과, 거의 같은 답안)와 문장 뱅크를 쓰지 않은 **보류 답안 6편**을 섞었습니다. 사람 검토용 표는 [`docs/essay-review.md`](docs/essay-review.md)이고, 고친 값은 `scripts/essay-overrides.json`에 적습니다.
- **AI는 제안만 합니다.** 기준별 수준·근거 문장·피드백 초안을 내고, 교수가 수락하거나 고쳐야 확정됩니다. 확정 전 점수는 분석에 넣지 않습니다.
- **모델 출력은 검증합니다.** 총점은 코드가 계산하고, 근거 인용이 답안에 실제로 있는지 확인합니다. 구조가 틀린 제안은 수락할 수 없고(직접 채점만), 근거가 맞지 않거나 지시문 주입이 의심되면 "검토 필요"로 수정 후 확정만 됩니다.
- **제공자:** 로컬 실행의 기본은 **기본 AI(화면 이름 "AI", 제공자·모델 id는 화면에 보이지 않고 기록에만 남음)**이고 로컬 중계를 거칩니다. 하루 100건·초당 1건 한도이고 작업마다 걸리는 시간이 길어(서술형 채점 약 1분, 태그·요약 초안 약 2분, 관계 초안 약 3분, 2026-11-11 실측) 화면에 경과 시간과 보통 걸리는 시간을 보여 주고, 5분 안에 답이 없으면 "다시 시도"를 안내합니다. Mock(키 없음, 규칙 기반, AI 아님)으로도 전체 흐름이 돌고, Gemini·Anthropic(공식 SDK)·OpenAI 호환 어댑터가 있습니다. 실제 키로 확인한 범위와 모의 fetch 계약 테스트만 한 범위는 `src/lib/ai/capabilities.ts`의 `verification`에 구분해 적습니다.
- **키는 "현재 브라우저의 개인 키 시연"입니다.** 기본은 메모리(새로고침하면 사라짐), 선택하면 sessionStorage입니다. localStorage·채점 기록·오류 메시지에는 남기지 않습니다. 키는 브라우저에서 제공자로 직접 전송되므로 운영 환경의 교수별 키 관리는 Moodle 서버 쪽 설계를 따라야 합니다.
- **Moodle 5.3 core에는 교수별 키 설정과 서술형 AI 채점 기능이 없습니다.** 관리자가 사이트 단위로 제공자와 키를 등록하고, 실패하면 다음 제공자로 자동으로 넘어갑니다. 설계 문서에 권장 단계와 샌드박스 확인 목록이 있습니다.
- 무료 등급 키는 입력이 제공사의 제품 개선과 사람 검토에 쓰일 수 있습니다. 데모에는 답안 붙여넣기 기능이 없어 가상 답안만 전송됩니다.

## AI 초안 3종: 개념 태그 · 개념 관계 · 결과 요약

결정·저장 계약·지표는 [`docs/decisions.md`](docs/decisions.md) §8, Moodle 5.3 적용 조사는 [`docs/moodle-ai-integration.md`](docs/moodle-ai-integration.md) §8에 있습니다.

- **AI는 초안만 냅니다.** 초안은 불변으로 쌓이고, 반영·확정 기록(문항별 태그 출처, 확정 관계, 확정 요약)은 근거 초안 id를 가리킵니다. 반영해도 편집 중인 값에만 들어가고, 저장은 교수가 누릅니다. 입력(문항·태그·응시·관계·그룹안)이 바뀌면 이전 초안은 반영할 수 없습니다.
- **태그 초안**은 학생 응답 없이 문항 내용만 보냅니다(퀴즈를 만든 직후에도 쓸 수 있음). 개념마다 근거 인용(지문·선택지·정답)을 받고, 인용이 그 출처에 실제로 있는지 검사합니다.
- **개념 관계**는 내용에 대한 교수의 판단입니다(선수·관련·혼동). 응답 겹침은 접힌 "중복 현황"(2×2)에서 참고로만 보여 주고 관계를 판정하지 않습니다. 선수 관계 순환은 저장하지 않습니다.
- **개념 묶음 보충 그룹**은 확정 관계로 이어진 개념들의 보충 그룹 **합집합**입니다. 데모 기본 태그에서 {시간복잡도, 정렬·탐색}는 17명(둘 다 7명)입니다. 새 오답률을 만들지 않고 학생마다 해당 개념 기준을 함께 보여 줍니다. 묶음이 쓴 관계가 바뀌면 그 그룹안만 재검토로 표시됩니다.
- **결과 요약**의 숫자는 모두 코드가 만든 사실 절입니다. AI는 `{F03}` 같은 사실 토큰을 골라 문장을 잇고, 토큰 밖 숫자·수량 표현·금지어가 있으면 "검토 필요"가 됩니다. 검토 표시를 모두 고쳐야 확정할 수 있습니다.
- **서술형 요약**도 같은 요약 작업과 검증기를 씁니다. 사실은 교수가 **확정한 점수만**으로 만들고(AI 제안 점수는 쓰지 않음), 확정이 없으면 실행할 수 없습니다(decisions §8.8).
- **실행 시점:** 코드 분석은 화면을 열 때 자동으로 계산하고, AI 초안은 교수가 버튼을 눌러 실행합니다. 동시 실행은 앱 전체에서 1건입니다.

## xAPI 원천 데이터

계획은 [`docs/xapi-plan.md`](docs/xapi-plan.md), 어휘와 규칙은 [`docs/xapi-profile.md`](docs/xapi-profile.md)에 있습니다.

- **퀴즈 응답의 정본은 xAPI Statement 파일입니다.** `public/xapi/quiz-w5.statements.json`(attempted 25 · answered 245 · completed 25건)에서 변환기(`src/lib/xapi/toDataset.ts`)가 `QuizDataset`을 만들고, 분석 함수는 바뀌지 않았습니다. 변환 결과가 전환 전 데이터(`tests/fixtures/quiz-w5.v1.json`)와 같음을 테스트로 확인합니다.
- **검증:** 모든 Statement가 Learning Locker `xapi-validation`(xAPI 1.0.3 기준)을 통과합니다(`public/xapi/quiz-w5.validation.json`). xAPI 2.0 수용은 실제 LRS에 보내 확인하기 전에는 주장하지 않습니다.
- **xAPI 기록 화면(`/xapi/`, 과정 홈 메뉴 "xAPI 기록"):** Statement 목록(동사·문항·학생 필터, 원문 JSON 펼치기), 빌드 때 만든 검증 보고서, Statement 파일과 보고서 내려받기. 검증 라이브러리는 브라우저 번들에 넣지 않습니다.
- **근거 보기:** 문항분석의 정답률, 개념 히트맵 셀(학급 행·학생 셀), 학생 상세의 점수를 누르면 그 숫자를 만든 Statement가 나옵니다. 예: "정답률 68% (17/25) — 정답 Statement 17건 · 오답 Statement 7건 · Statement 없음(무응답) 1명". 개념 셀은 지금 편집 중인 Q-matrix로 문항을 고릅니다. Statement 파일은 처음 누를 때 한 번만 받고, 변환기와 같은 대응표(`sources`)로 근거를 찾습니다(`src/lib/xapi/evidence.ts`). 근거 건수가 화면 숫자와 다르면 `tests/xapi-evidence.test.ts`가 실패합니다.
- **원자료 내려받기:** 배포된 사이트의 `/xapi/quiz-w5.statements.json`.
- **아직 없는 것:** 서술형 확정 점수 Statement, 태그·관계·그룹안 문서 내보내기, LRS 왕복 시연(계획 P3–P4). IRI 도메인은 임시(`learnlens.example`)이고, Tube LRS 샌드박스·기존 어휘·서술형 원천은 MVP 통과 후 정합니다.
- 학생은 가명 id(`account.name = s01`)로만 식별하고, 모든 Statement에 `context.platform = "LearnLens demo (synthetic)"`를 붙입니다. 시간 값도 생성한 값입니다.
